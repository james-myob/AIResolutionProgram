Architectural choice 6 / 10

Why Claude Code Routines, not GitHub Actions

Standard answer for "run this daily" is a GitHub Actions cron. I went the other way. Here's why.

GitHub Actions cron Claude Code Routine
News gathering Brittle Python: parsing RSS, scraping HTML, fragile to layout changes Native WebSearch + WebFetch, adapts to layout changes
Editorial judgement Has to be encoded in code (it can't) Literally what Claude is for
Failure modes Hard fails on unexpected input Reasons through edge cases, notes them in the briefing
Auth / billing Needs ANTHROPIC_API_KEY + per-token billing Uses existing Claude Code subscription
Maintenance Per-source code maintenance "Update the source list" = edit one Markdown file

The insight: news gathering + editorial judgement is irreducibly agentic. Scripting it would mean re-implementing Claude in Python — and losing every advantage the model gives me.

Pragmatism 7 / 10

What I deliberately didn't automate (and why that's fine)

Two pieces of the pipeline still need a human paste. I kept them manual on purpose.

🎧

Weekly NotebookLM audio

Paste the weekly Markdown into NotebookLM, click "Generate Audio Overview".

Google's consumer audio API doesn't exist yet. Enterprise API exists but isn't worth the bill for a personal workflow.

~2 minutes, once a week.

📊

Monthly Claude Design deck

Paste the monthly Markdown into claude.ai/design, get a deck back, export PPTX.

Claude Design is still research preview — no public API.

~5 minutes, once a month.

~13 min / month
total human-attention time across the whole pipeline

The lesson: "must automate everything" is a great way to never ship. A pipeline that's 95% automated and runs for years beats one that's 100% automated and never quite gets out the door.

Takeaways 8 / 10

5 lessons that transfer to any AI-driven workflow

  1. Two-lens framing doubles value at low cost. "Why it matters for X" + "Why it matters for Y" — pick two lenses your audience actually has, ask both questions of every item.
  2. Structured metadata is leverage. YAML front-matter on each Markdown file drove email subject lines, deck URLs, and search indexes — all generated, not hand-maintained.
  3. Tag discipline compounds. A consistent taxonomy looks like overkill on day 1 and pays off on day 30 when you can search "everything that mentioned Anthropic this quarter".
  4. Manual paste steps are acceptable. When the API doesn't exist, design around it instead of waiting for it. Most of the value lives in the corpus, not the delivery channel.
  5. Match the tool to the task. Agentic work (judgement, synthesis, fuzzy inputs) belongs in agents. Deterministic work (HTTP requests, file IO) belongs in scripts. Don't force one into the other.
