Architectural choice 06 / 10

Why Claude Code Routines, not GitHub Actions

Default answer for "run daily" is a cron. I went the other way — here's why.

GitHub Actions cron Claude Code Routine
News gathering Brittle Python: RSS parsing, HTML scraping, fragile to layout changes Native WebSearch + WebFetch, adapts to layout changes
Editorial judgement Has to be encoded in code — it can't Literally what Claude is for
Failure modes Hard fails on unexpected input Reasons through edge cases, notes them in the briefing
Auth / billing Needs ANTHROPIC_API_KEY + per-token billing Uses existing Claude Code subscription
Maintenance Per-source code maintenance "Update the source list" = edit one Markdown file
The insight. News gathering plus editorial judgement is irreducibly agentic. Scripting it would mean re-implementing Claude in Python — and losing every advantage the model gives me.

Pragmatism 07 / 10

What I deliberately didn't automate

Two pieces still need a human paste. I kept them manual on purpose.

🎧

Weekly NotebookLM audio

Paste weekly Markdown into NotebookLM, click "Generate Audio Overview".

No public consumer API. Enterprise API exists but isn't worth the bill for a personal workflow.

~2 min / week

📊

Monthly Claude Design deck

Paste monthly Markdown into claude.ai/design, get a deck back, export PPTX.

Claude Design is still research preview — no public API yet.

~5 min / month

~13 min / month
total human-attention time across the whole pipeline
The lesson. "Must automate everything" is a great way to never ship. A pipeline that's 95% automated and runs for years beats one that's 100% automated and never quite gets out the door.

Takeaways 08 / 10

5 lessons that transfer to any AI workflow

  1. Two-lens framing doubles value at low cost. Pick two lenses your audience actually has — ask both questions of every item. Cost of the second question is near zero; value of the second answer is huge.
  2. Structured metadata is leverage. YAML at the top of every Markdown file in this pipeline drives email subject lines, deck URLs, and search indexes. None of it is hand-maintained. Invest in structure on day one.
  3. Tag discipline compounds. A consistent taxonomy looks like overkill on day one and pays off on day thirty when you can search a quarter of history in seconds.
  4. Manual paste steps are acceptable. Most of the value lives in the corpus, not the delivery channel. If the API doesn't exist, design around it instead of waiting for it.
  5. Match the tool to the task. Agentic work belongs in agents — judgement, synthesis, fuzzy inputs. Deterministic work belongs in scripts. Don't force one into the shape of the other.
