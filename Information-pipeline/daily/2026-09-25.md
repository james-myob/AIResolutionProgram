## 🧠 Models & Capabilities

### Anthropic ships Claude Opus 5.5, cutting price 40% while matching Fable 5.1 on most work
Anthropic released Claude Opus 5.5 two months after Opus 5, pricing it at $4/$20 per million input/output tokens (down from $5/$25) and cache reads at $0.20 (down from $0.50), while generating output over 30% faster. Anthropic says the model matches Claude Fable 5.1 on most tasks and cites a test where it helped migrate 680,000 lines of code in under a day.
**Why it matters (PM):** This is a capability jump sold primarily as a price cut, not a benchmark chase — expect procurement conversations to shift from "which model is smartest" to "which model is cheapest at the capability tier you actually need."
**Why it matters (mid-market):** Cache-read pricing (down 60%) disproportionately helps agent-heavy workflows that resend context repeatedly — a meaningful cost lever for mid-market products built on Claude that couldn't previously make the unit economics work.
**Sources:** [Anthropic](https://www.anthropic.com/claude-opus-5-5) · [TechCrunch](https://techcrunch.com/2026/09/22/anthropic-releases-opus-5-5-with-lower-prices-and-fable-level-performance/) · [Simon Willison](https://simonwillison.net/2026/Sep/22/opus-and-sol-and-luna/)

### OpenAI answers within the hour: GPT-6 Sol and Luna launch at 50% lower API prices
About ninety minutes after Anthropic's Opus 5.5 release, OpenAI shipped GPT-6 Sol and Luna — smaller, cheaper siblings of its GPT-6 Astra flagship (released 3 September) built with the same alignment and factuality work. Sol drops to $2/$10 per million tokens (from $4/$20), and Luna to $0.10/$0.50 (from $0.20/$1.20), among the cheapest models OpenAI has shipped.
**Why it matters (PM):** Two frontier labs cut prices in lockstep on the same day — treat that as a signal the floor for "acceptable" AI feature cost just moved, not a one-off promotion; any cost model you built even a month ago needs a re-check.
**Why it matters (mid-market):** Luna's price point puts near-frontier reasoning within reach of free/low-tier product tiers — a mid-market SaaS vendor can now plausibly embed AI features in a base plan rather than gating them behind an add-on.

## 📦 Products & Tooling

### TypeSafe launches Jev, a "System One" model that trades text generation for typed, calibrated decisions
TypeSafe introduced Jev, the first model in a category it calls "System One models" (a Kahneman reference): instead of generating text, it takes text in and returns floating-point decisions — categories, yes/no answers, ratings — with confidence scores, at $0.042 per million input tokens with free output. Willison reports it matches LLM-level accuracy on classification-style tasks while running roughly two orders of magnitude faster.
**Why it matters (PM):** For any feature that's really a classification or routing decision wearing an LLM costume (triage, moderation, scoring), this is a cheaper, structurally non-hallucinating alternative worth benchmarking against your current prompt-based approach.
**Sources:** [Simon Willison](https://simonwillison.net/2026/Sep/21/jev/) · [TypeSafe](https://typesafe.ai/blog/introducing-system-one-models-and-jev)

## 📒 New Concepts

### System One Models (Decision Models)
**Plain English:** A new category of model, distinct from a chat-style LLM, that takes unstructured text as input but never generates text as output — instead it returns structured, typed decisions (a category, a yes/no, a rating) each with a confidence score. The name references Daniel Kahneman's "System 1" fast, intuitive thinking, as opposed to the slower, deliberate reasoning that chat-oriented LLMs are tuned for. Because the output space is constrained to valid structured values, the model can't hallucinate a nonsensical answer the way a text-generating LLM can. Positioned as a cheap, fast substitute for using a general-purpose LLM to make a classification or routing decision.
**Origin:** [Simon Willison — Jev introduces a new shape of LLM](https://simonwillison.net/2026/Sep/21/jev/) · [TypeSafe](https://typesafe.ai/blog/introducing-system-one-models-and-jev)
